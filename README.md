# مِرفق

منصة عربية لإدارة بلاغات صيانة العقارات في السعودية. تربط مدير العقار والساكن والفني من تسجيل البلاغ حتى توثيق الإنجاز وإصدار التقارير.

## ما الذي يعمل؟

- إدارة عدة عقارات ووحدات من حساب منشأة واحد.
- حسابات وصلاحيات مستقلة للمدير والساكن والفني.
- إنشاء البلاغات وإسنادها والتعليق عليها وتحديث حالتها.
- رفع صور أولية وصور إتمام.
- أوامر عمل وتقارير شهرية قابلة للطباعة.
- إعدادات وهوية خاصة بكل منشأة وسجل عمليات.
- رمز QR قابل للتنزيل والتجديد لكل وحدة.
- صفحة أسعار ونموذج فعلي لطلبات العروض.

## ميزات Phase 2

- صفحة بلاغ عامة لكل وحدة عبر رمز QR، بدون إنشاء حساب أو تسجيل دخول.
- حماية صفحة QR بحدود طلبات مزدوجة، دون كشف بيانات الساكن، مع حفظ بيانات مُبلّغ الصيانة.
- تسجيل تكلفة العمالة وقطع الغيار وإظهار إجمالي تكلفة كل بلاغ.
- تقييم البلاغ المكتمل من الساكن بنظام 1–5 نجوم وتعليق اختياري.
- خطط صيانة وقائية مرتبطة بالعقار أو الوحدة والفني.
- تكرار تلقائي لموعد الخطة بعد إكمال دورة الصيانة، مع تفعيل الخطة أو إيقافها.
- مؤشرات تشغيلية للتكاليف ورضا السكان وخطط الصيانة القريبة.

## التشغيل محليًا

المتطلبات: Node.js 20 أو أحدث وpnpm 11.

```bash
pnpm install
pnpm run dev
```

أول تشغيل ينشئ قاعدة SQLite جديدة تلقائيًا في `artifacts/api-server/.data/mirfaq-local.db`، ثم يطبّق المخطط والبيانات التجريبية قبل تشغيل الخادم. لا يعتمد التشغيل على ملف `prisma/dev.db` القديم.

افتح `http://localhost:5173`.

التشغيل المحلي لا يحتاج اشتراك Replit أو API مدفوعة: قاعدة البيانات SQLite والملفات محفوظة على الجهاز. النشر الدائم على الإنترنت منفصل، وتكلفته تعتمد على مزود الاستضافة المختار.

- `technician@mirfaq.sa`

## متغيرات الإنتاج

انسخ `artifacts/api-server/.env.example` واضبط:

- `MIRFAQ_DB_URL`
- `SESSION_SECRET` بقيمة عشوائية لا تقل عن 32 حرفًا.
- `APP_ORIGINS` بأسماء النطاقات المسموحة مفصولة بفواصل.
- `PORT`

SQLite والتخزين المحلي مناسبان للعرض التجريبي والبدايات. عند وجود عملاء فعليين، انقل قاعدة البيانات إلى PostgreSQL والمرفقات إلى تخزين كائنات متوافق مع S3.

## التقنية

React، TypeScript، Vite، Tailwind CSS، Express، Prisma، SQLite، TanStack Query وpnpm workspaces.
